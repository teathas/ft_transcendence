# Languages and direction

The app ships in **English, French and Arabic**, and lays itself out right to
left for Arabic.

Seven files make it work. In the order they were built:

| # | File | What it does |
|---|---|---|
| 1 | `src/i18n/config.ts` | the list of languages, their direction, their names |
| 2 | `src/i18n/dictionaries/{en,fr,ar}.ts` | the phrases |
| 3 | `src/i18n/translate.ts` | fills in `{placeholders}` |
| 4 | `src/i18n/server.ts` | reads the language in a Server Component |
| 5 | `src/i18n/client.tsx` | reads the language in a Client Component |
| 6 | `src/proxy.ts` | sends a URL without a language somewhere sensible |
| 7 | `src/i18n/navigation.tsx` | keeps the language in every link |

## 1. The languages

`config.ts` is the only list. The proxy, the switcher and
`generateStaticParams` all read it, so adding a language starts here.

## 2. The dictionaries

Plain nested objects. **English is the source of truth**: `Dictionary` is
`typeof en`, and the other two are declared `satisfies Dictionary`, so a key
missing from French or Arabic breaks the build instead of leaving a blank spot
on screen.

Reading one is ordinary property access — TypeScript checks it for free, and
`d.rooms.titel` does not compile:

```tsx
const d = useDict();        // Client Component
const d = await getDict();  // Server Component

<h1>{d.rooms.title}</h1>;
```

## 3. Placeholders

Most phrases are plain strings. The few that carry a value use `{braces}` and go
through `t`, so you can see at a glance which ones they are:

```tsx
import { t } from "@/i18n/translate";

t(d.pagination.showing, { from, to, total });
```

`t` is one function, ten lines: it replaces each `{name}` with its value. No
hook, no context — it does not depend on the language, because the phrase it
receives is already in the right one.

Phrases are written to read correctly whatever the number ("Page {page}",
"{count} archived"), so no language needs plural rules.

## 4 & 5. Reaching the language

Every page lives under `app/[lang]`, so `lang` is a *root parameter* and
`next/root-params` reaches it from any Server Component without threading it
through props. That is all `server.ts` does.

For the browser, the root layout puts the locale and its dictionary into a
context (`client.tsx`), and `useDict()` reads it. The whole
dictionary crosses — a few kilobytes — so no component has to await anything
to render a label.

## 6. The proxy

`/rooms` has no language in it, so `proxy.ts` picks one and redirects: the
language the visitor last chose (a cookie it writes itself), then
`Accept-Language`, then English. An Arabic browser asking for `/rooms` lands on
`/ar/rooms`.

The language is in the URL rather than only in a cookie because that makes an
Arabic page linkable, and lets Next prerender all three as static HTML.

## 7. Links

Never import `next/link` — ESLint blocks it. `Link` from `@/i18n/navigation`
prefixes the active language, and `useLocaleRouter()` does the same for
`push`/`replace`. `routes.ts` keeps listing paths the way they read (`/rooms`,
not `/[lang]/rooms`).

For an active-link check, `useBarePathname()` strips the prefix so
`pathname === routes.rooms` holds in all three languages.

## What `Intl` handles, the dictionary does not

Dates, relative times and weekday names are never written by hand — every
language already ships them:

- `useFormat()` (`src/lib/format.ts`) — "3 minutes ago", "il y a 3 minutes",
  "قبل 3 دقائق", and the Arabic dual "قبل ساعتين" for two hours.
- `useActivityFormat()` — weekday names for the dashboard chart (L M M J V S D
  in French).

The language comes from the URL, not the visitor's operating system, which is
what keeps a French timestamp out of an Arabic page.

## Right to left

`<html dir>` is set from the language in `app/[lang]/layout.tsx`. Everything
else follows from **logical CSS**: `ms-`/`me-`, `ps-`/`pe-`, `start-`/`end-`,
`text-start`, `rounded-s-`, `border-e`. There is no mirrored stylesheet.

Three things cannot be expressed logically and are mirrored by hand:

- `translate`, which has no logical form — the mobile drawer carries
  `-translate-x-full rtl:translate-x-full`.
- Directional icons — an arrow meaning "onward" gets `rtl:rotate-180`.
- `space-x-*`, which needs `rtl:space-x-reverse`.

Content that is not prose keeps its own direction: the worked equation on the
landing board and people's names are wrapped in `dir="ltr"`.

Arabic is set in Noto Sans Arabic, loaded beside Geist, which carries no Arabic
glyphs.

**tldraw localises itself.** `useBoardIdentity` pushes the locale onto the
editor and the whiteboard's menus, tooltips and panel placement follow —
including its own right-to-left layout.

## Validation messages

Zod schemas carry **keys into `dictionary.validation`**, not sentences:

```ts
username: z.string().min(3, "usernameMin");
```

`FieldError` looks them up at render, which is the only moment the language is
known. Anything it does not recognise is shown unchanged — which is what lets
an error sentence written by the API travel the same path untouched.

## Adding a language

1. Add it to `locales` in `config.ts`, with its direction and its own name.
2. Copy `dictionaries/en.ts`, translate it, declare it `satisfies Dictionary`.
   TypeScript lists anything missing.
3. Register it in `dictionaries/index.ts`.

## Adding a phrase

Add it to `en.ts` first — the build then tells you it is missing from French
and Arabic.
